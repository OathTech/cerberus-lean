## 2. The incomplete-run rule

A batch observation that contains ANY stop record — `Exhausted {}`, `ModelFailure {…}` or `Unsupported {…}`, under any execution header, beside any number of `Defined`/`Undefined`/`Error` lines — is **INCOMPLETE**: it is never semantic agreement, never a reference/pin projection, never compared as a set or a successful prefix (contract v1 §"Completion and failure"; review §7). Its completion class is the stop kind (`exhausted` | `model_failure` | `unsupported`). Exit policy is UNCHANGED and OCaml-parity: single `Defined` → 0, single kill (including a stop) → 1, multiple executions → 0 (`Main.lean:1083-1086` today, prototype `:1121-1125`; `backend/driver/main.ml:runM`), and the codec keeps checking the actual status against that protocol (`observations.py:328-331`) — the incomplete classification is carried by the RECORD, not by the exit status (a multi-execution batch with one `Exhausted {}` exits 0 and is incomplete). An OCaml uncaught exception aborts the whole exploration (`FATAL`, `observations.py:47-48`); a Lean branch-local stop leaves the other branches' records in the batch — the harness must not drop the stop and compare the survivors.

## 4. The legacy-text rule

After S1 the string `lem: fuel exhausted` carries NO meaning anywhere in the batch protocol: an ordinary `Error {msg: "lem: fuel exhausted"}` (a Core `error("lem: fuel exhausted")`, or any model error that happens to spell it) is an ORDINARY error — `ERR`, comparable, never FUEL, never incomplete. The old current-run string test is NOT kept as a compatibility alias for structural exhaustion (`FUEL_RECORD`'s first alternative and `FUEL_KILL_BATCH_LINE` are deleted, not widened). Historical captures (e.g. `.tmp` release logs) that contain the old line are NOT decodable as exhaustion by the default codec; if S1 wants them, it adds an explicitly selected legacy decoder (`--legacy-fuel-text`, off by default) — [AGENT] recommended: do not add one; no committed baseline holds a FUEL row (seven files checked 2026-09-16, charter §1), so nothing committed needs it. The plant of this rule is `stub_legacy` (§3, `test_fuel_plant.sh`) and `test_fuel_classifier.sh`'s flipped cases.

## 5. Pure exhaustion PANICS keep their class

The pure-return fuel'd workers (`hack` = `fuelExhausted Vunit`, `pull_constrained`, `step_eval_pexpr` = value sentinels; LemLib's `fuelExhaustedWith`) exhaust as a PANIC line `lem: fuel exhausted` on stderr under `LEAN_ABORT_ON_PANIC=1` (exit 134), not as a record. Their classification is unchanged: `fuel_classify.sh:55-56` `FUEL:panic` (rc ≥ 128 + the bare line), `observations.py:49-52`'s three panic alternatives (→ `'fuel exhausted; exploration incomplete'`), the lanes' `FUEL`/`LEAN_CRASH` families. Replacing the typed record must not remove this recognition (review §7); `test_fuel_plant.sh`'s `stub_panic` (`:37-40`) is the plant.

## 6. Adversarial payloads and the admission layer

- `msg` fields are `ESCAPED` (`observations.py:37`) through `CerbEscape.text` (UTF-8 bytes; quotes, backslashes, newlines, control bytes escaped; Unicode as bytes) — the existing byte/text distinction (contract v1 §"Main.batchEscape producer trace" `:151-169`); `Exhausted {}` carries no payload; `feature` is a closed alternation. Records are matched as WHOLE lines (`fullmatch`, `observations.py:308-317`); protocol-looking text inside a program's stdout/stderr lives inside the `Defined` record's escaped field and cannot form a record (the `stub_words` plant, `test_fuel_plant.sh:41-45`; `test_fuel_classifier.sh:57-59`). Anything else that starts with `Unsupported {` or `Exhausted {` and does not fullmatch is a malformed record → `ProtocolError` (`:318-319`), never a verdict. Adversarial cases to add to `test_observations.py`: a msg containing `"} Defined {value: "`, a msg with a newline (must be escaped or the record is malformed), a NUL byte, a 4-byte UTF-8 character.
- The CLI `refuseFlag` (`lean_frontend/Main.lean:1188-1199`: unknown `--flag` → message + `IO.Process.exit 2`, before any run) is an ADMISSION rejection and is UNCHANGED: exit 2, no batch record, not an `Unsupported` record (the vocabulary may be shared for the message text only). `observations.refusal` (`:178-184`) and the concurrency prototype's `model refused: …`-prefixed `Error` convention (`test_observations.py:305-309`) are unchanged by S1; whether the latter migrates to an `Unsupported {feature: "concurrency", …}` record is S2's (the refusal census's) question. Host OOM (`cap_oom.regex`), timeout, signal death and malformed output remain harness failures (`observations.py:264-268, :291-292`), never `FailStop`.
