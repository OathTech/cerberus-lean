## 4. Walker v2 → v3: the measured engine findings

Each finding is from a probe run on the T5 entry theorem
(`app (dnms5 (fuel+21)…) (post-prefix) = app (dnms5 fuel…) (StT5 n 0)`,
scratch probe, deleted; reproducible from this record).

* **F-S3-1 (atom pred).** Fixture-name preservation must live INSIDE
  whnf (`withCanUnfoldPred`), not in post-hoc head checks — and the
  predicate must be installed ONCE per normalization (a fresh closure
  per whnf call busts the whnf cache; measured 25s on one eval
  round, ~60ms after hoisting).
* **F-S3-2 (map-valued blocking).** The state normalizer's unfold
  predicate additionally blocks constants whose RESULT type is
  map-valued (Fmap/TreeMap): `{σ with …}.field` chains collapse to
  compact field values while `fmapAddBy`/`insert`/
  `create_extern_symmap` never materialize tree internals. But the
  DISCOVERY path must NOT use it: the program itself lives inside an
  Fmap (`t5File.funs`), so discovery computation needs full
  unfolding (normPayload/normCompute).
* **F-S3-3 (scalar folding).** Supplies/addresses must fold to
  literals or the state self-embeds (the tid_supply finding: a
  projection-of-the-whole-previous-state spelling snowballs
  exponentially). Type classification must WHNF the type (thread_id/
  aid are abbrevs of Nat). Full `Meta.reduce` is BANNED for this
  (it normalizes the whole argument — measured to materialize state
  trees and hit the 40G cap); `evalScalar` (whnf head + scalar-arg
  recursion + re-whnf) is the targeted engine.
* **F-S3-4 (sizeWithoutSharing).** Exponential on shared DAGs —
  measured as multi-minute hangs in size-arbitration/tracing;
  replaced by the cached `approxDepth`.
* **F-S3-5 (THE ELABORATOR WALL, cleared).** The elaborator's
  substitution-based whnf blows the memory cap (>40G) on
  deep-context eval-round crossings the compiled evaluator does in
  ms and the kernel does in ~60ms. Discovery whnf now goes through
  `Kernel.whnf` (`kWhnf`; meta fallback on mvars/errors). This
  cleared rounds that were previously unreachable: with it the
  walker mechanically discharges ALL 21 entry rounds — including
  the two CREATE and two STORE action rounds end-to-end
  (dnms_round + advance_action_request + perform_create/store +
  mem_alloc/store_block + mem_prefix_block), at 50–300ms per
  mechanical round (~1.7s for the heaviest create round), ~73s for
  the whole entry elaboration.
* **F-S3-6 (heartbeat ledger).** The S2 per-round-window accounting
  was incomplete: `withCurrHeartbeats` shields the round, but the
  consumption still lands on the ENCLOSING tactic meter. The walker
  now settles the ledger after each capped round
  (`IO.getNumHeartbeats`/`IO.setNumHeartbeats` restore) — each round
  individually capped at ambient, total bounded by round-budget ×
  ambient, exactly the budget of the per-round declaration files
  this replaces. No set_option, no ambient raise; flagged here for
  the audit.
* **F-S3-7 (head-filtered assumption).** Plain `assumption` walks
  every context hypothesis with full-size isDefEq (measured seconds
  at action-round term sizes, and a silent multi-second hang on one
  hypothesis class); an equation hypothesis is now tried only when
  its LHS head constant matches the goal's — preserving the
  context-fed block-fact design at no cost.
* **F-S3-8 (ctor-pattern computed values).** Computed-value
  hypotheses with constructor-pattern RHS (`(NDactive ?v, ?σ)`,
