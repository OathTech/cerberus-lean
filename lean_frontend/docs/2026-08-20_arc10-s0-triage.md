## Chosen S4 run parameters

- **Generator flags, lane V (default, mismatch-hunting):**
  `--no-argc --no-bitfields --max-funcs 3 --max-block-depth 3
  --max-block-size 4 --max-expr-complexity 3 --max-array-len-per-dim 8`
  (kit flags + the array-len cap; validated: same yield, seed-930005
  hit still reproduces).
- **Lane NV (value-purity):** lane V + `--no-volatiles
  --no-volatile-pointers` — removes the volatile/pointer-fork
  trace-count noise so value-semantics bugs surface; measured yield
  7/20 → 9/20 when also `--no-packed-struct` (packed structs kept ON in
  lane V for coverage; a `--no-packed-struct` variant is the fallback
  if AilEinvalid skips flood).
- **Loop/ceiling rationale:** csmith 2.3.0 has no direct loop-count
  flag; its loops are array-bounded, so `--max-array-len-per-dim 8`
  with block depth ≤3 bounds nest products at 8³ = 512 iterations —
  under the charter's ~1k guidance and >30x under today's measured
  ceiling onset (~16-24k). `--float` stays off (default) — keeps the
  upstream float-mul doc-delib divergence unreachable.
- **Seeds:** deterministic and recorded, `CSMITH_SEED_START` per batch;
  no wall-clock/randomness. Reserved (already burned) ranges:
  910001-910010 (smoke), 920001-920020 + 930001-930020 (flag probes).
  Proposed S4: lane V from 1000001, lane NV from 2000001, batches of
  100 (the kit takes N + start; batch boundaries = commit/tally
  boundaries).
- **Timeouts:** `TIMEOUT_SECS=15` per side per test (`timeout` wraps
  both the oracle and the Lean binary inside test_exec.sh; smoke
  comparables all finished well inside).
- **Memory:** every batch, and every creduce reduction, runs under
  `scripts/capped` with `CERB_MEM_MAX=8G` — one cgroup enclosing BOTH
  sides and the harness (the operator's standing memory-bounds rule;
  note: an inner capped invocation, e.g. build_lean's, opens a sibling
  scope with its own cap — everything stays capped).
- **creduce:** via `scripts/creduce` wrapper, `--n 1` (see open
  question 2), `TIMEOUT_SECS=15`, `INTERESTING_REGEX` = the classified
  status, `EXPECT_SNIPPET` = the pinned per-file-line signature.
- **Classification buckets** (harness statuses, subdivided per what the
  shakedown showed): MATCH / UB_MATCH / UB_DIFF /
  **MISMATCH_VALUE** / **MISMATCH_TRACE_COUNT** (same value multiset,
  different execution count — observed, seed 930005) / DIFF (one-sided
  UB) / **LEAN_PANIC** (LEAN_CRASH with a PANIC line) / **CEILING**
  (LEAN_CRASH exit 134, no PANIC line, loop-heavy reproducer) /
  LEAN_ERROR / TIMEOUT_LEAN / **CERB_SKIP_INTERNAL** (exit 125,
  AilEinvalid class — counted, upstream-attributed) / CERB_SKIP_OTHER /
  CERB_INCONSISTENT. Both-sides-timeout invisibility caveat applies
  (oracle runs first).
- **Scale:** ~20 generated programs ≈ 2-3 min wall including skips →
  O(10³) programs per lane is hours-scale; per charter, run until the
  triage queue is the bottleneck and report N achieved.
