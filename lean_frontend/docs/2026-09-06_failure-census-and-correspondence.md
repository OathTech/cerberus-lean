# Deliberate failures: census and correspondence proposal

2026-09-06 [AGENT], validation-foundations G6. The larger representation
change below is a proposal for the operator's final design discussion.
This charter changes no Lem body, generated semantics, failure representation,
or fuel policy. Its runnable instruments identify what the next repair must
establish. The [earlier design](2026-09-05_typed-failure-outcomes-design.md)
remains historical; its sampled counts are superseded here.

## Source and measurement discipline

The development census uses Cerberus's semantic sources at `5d2f380de`
(unchanged from assessed mainline `89f7e6885`) generated by Lem `f6542f8`.
The cold provider rehearsal separately rebuilt that compiler, its OCaml
libraries/runtime, and Cerberus. Strictness probes use that owned compiler
and runtime, Lean 4.32.2 and OCaml 5.4.0. No shared installation was changed.

Both instruments were then rerun directly against the final cold build of
`1066d89eea16f55a0f204f95c351731629df296a`. All eight observations, every
census site/classification and its source hash match the development results.
All 207 generated Lean and 86 generated OCaml file hashes also match. The
rebuilt compiler and four OCaml runtime archive hashes differ, so no binary
identity was assumed: the final probes used the final compiler/runtime.
See the [comparison and direct-reproduction record](validation-foundations-evidence/provider-evidence-comparison.json)
and [final raw archive](validation-foundations-evidence/final-provider-failures.tar.gz).

Reproduction, in the project environment after the
[provider recipe](2026-09-06_provider-smoke.md):

```bash
python3 scripts/run_failure_probes.py \
  --provider-manifest .validation-foundations/provider-cold/manifest.json \
  --out .validation-foundations/failure-probes
python3 scripts/run_failure_census.py \
  --provider-manifest .validation-foundations/provider-cold/manifest.json \
  --out .validation-foundations/failure-census
```

The JSON census records file, line, column, character offset, declaration,
failure token, type ascription, message-source excerpt and source hashes for
every site. Nested comments, strings and character literals are lexed; a
colon inside a computed message cannot terminate the type search. Tests
cover those cases, including the character literal containing a double quote.
Handwritten files copied into `generated/` are counted only at their source.

The Lean instrument reuses `FuelFormsTool.closure`, including mutual blocks,
over the actual public execution and frontend roots. It reports opaque
declarations too and supplies compiler declaration ranges to identify
anonymous instances. A constant dependency is an upper bound on potential
use, **not a witness that a failing branch executes**. Conversely, absence
from the kernel closure does not establish absence from compiled partial
frontend code. No site is declared proved unreachable on that evidence alone.
Two sites (`CoreParser.scanStep`, `Main.loadCoreImpl`) are outside the imported
instrument modules and remain unresolved explicitly.

## Corrected census

The first audit (VF-06) found that lexical declaration names could borrow
another definition's dependency flags. The repaired mapper always requires
compiler range containment, chooses the unique smallest enclosing range,
and exposes ambiguity/import gaps explicitly. Lexical names remain hints;
canonical `definition` and `kernel_names` record the compiled owner. Replaying
against the same hash-matched source and compiler log preserves all 1,644
sites and fixes 30 false execution-dependency assignments. The table below
uses that corrected mapping: pure execution-dependent sites are **231**,
not the historical 261. Historical raw files remain unchanged; see the
[audit repairs](2026-09-06_validation-foundations-audit-repairs.md).

### The seven memory-monad arms

| Current source | Existing obligation and reachability classification |
|---|---|
| `CerbMem.lean:2093`, `allocator`, zero alignment | Host division-by-zero classification already awaits a ruling; `_Alignas`/allocation validity is not a blanket frontend theorem. Preserve its input and exact reference behavior before choosing the failure class. |
| `:2123`, `allocateObject`, requested address | Deliberate `cerb::with_address` refusal. The API can request it; no general proof excludes it from C. |
| `:2216`, `killM`, dead static allocation | Deliberate reference fail-stop. Core/API state can trigger it; C reachability depends on allocation/address invariants that are not proved here. |
| `:2704`, `effArrayShiftPtrval`, function pointer | Deliberate reference fail-stop. The typed API admits this pointer constructor; source-level exclusion needs a checked typing invariant. |
| `:2774`, `memcmpM`, non-integer byte | Reference assertion. Requires memory representation invariants, including byte contents; no general memory well-formedness preservation theorem is supplied here. |
| `:2963`, `vaList`, nonzero index | Reference assertion. Requires the varargs representation invariant; arbitrary API inputs can violate it. |
| `:2982`, `callIntrinsic`, CHERI | Feature refusal. The default configuration is definitionally non-CHERI, but that fact alone is not a call-site reachability proof for every public Core API. |

The available ND kill is `NDkilled (Error0 loc msg)`; `nd_bind` propagates
it and `liftMem` maps it into the driver. Reusing an existing shape still
requires a distinguishable model-failure classification and propagation
theorems, including the runner and observation printer. A model fail-stop
must not silently become the model's ordinary UB or recoverable error.

### Channels and the historical five exceptions

The 37 generated ND sites have an explicit `Error0` location/message channel.
The 26 execution-dependent `t0` sites can use an `Error` inside the state/
exception result. Function-valued ascriptions need an actual failing function
at the state argument; substituting a monadic value at the wrong type is not
a transformation rule.

The four historical stack operations return `exceptM X core_run_cause` with
non-`t0` `X`. The new census also finds four such sites in the execution-used
`Core_eval.call_function`. `core_run_cause` has an `Unresolved_symbol loc sym`
constructor, but has **no general deliberate-failure constructor carrying
the required payload**. Calling the whole type location-free was imprecise;
abusing `Unresolved_symbol` or `Found_empty_stack` changes the failure class.

The historical fifth site, `AilTypesAux.lvalue_conversion`, uses `errorM`.
`ErrorMonad.lean:44` already carries `Loc × typing_error`; the missing design
is a faithful model-failure alternative, not the physical presence of a
location field. Frontend `Errors.error` is likewise `Loc × cause`.
The inventory keeps these distinct from ND and `t0`, and from the partial
frontend's separate termination/compiled-call-graph obligations.

## Strictness mechanisms actually measured

[The Lem input](../../tests/failure-probes/discarded_failures.lem) is compiled
to both targets. Every invocation receives its argument at runtime. Raw
stdout, stderr, exit status, binaries' hashes and generated sources are kept.
Lean runs with `LEAN_ABORT_ON_PANIC=1` in both execution modes.

| Mechanism | OCaml | Lean native and interpreted | Kernel equation |
|---|---|---|---|
| Unused binding | Failure, exit 2 | Prints 1, exit 0 | Result equals `n + 1` |
| Unused argument | Failure, exit 2 | Prints 1, exit 0 | Result equals `n + 1` |
| Projection discards failing tuple component | Failure, exit 2 | Prints 1, exit 0 | Result equals `n + 1` |
| Discarded result of `List.map` | Failure, exit 2 | Prints 1, exit 0 | Result equals `n + 1` |
| Callback result discarded by its caller | Failure, exit 2 | Prints 1, exit 0 | Result equals `n + 1` |
| Length of a mapped singleton discards its failing element | Failure, exit 2 | Fails: native SIGABRT, interpreted 134 through the cap wrapper | Result equals 1 |
| Required failure control | Failure, exit 2 | Both fail | No successful-result equation claimed |
| Positive control | Prints 1, exit 0 | Prints 1, exit 0 | Ordinary successful value |

All six displayed equations are checked by `rfl`, with no axioms in their
printed cones. The mapped-singleton example separates logical reduction from
compiled evaluation; runtime abort behavior is not a logical failure theorem.
These are demonstrated Lem/Core API mechanisms, not demonstrations that all
six shapes currently occur on a reachable C path.

There are independently identified C-triggered failures: null pointer
arithmetic (`tests/minimal/097-null-ptr-arith.undef.c`, `CerbMem:1726`), the
device function-pointer call (`tests/immaculate/nolibc/zd-z2m02-device-funptr-call.c`,
`CerbMem:1379`), and `closedir` refusal
(`tests/immaculate/libc/zd-z2f04-closedir.c`, `CerbFS:519`). The first has
current independent-oracle captures; the others have their existing
immaculate reproducer/pin and current lane evidence. Matching crashes are
not semantic result agreement. A precondition invoked for any other site
must be proved or enforced, rather than copied from a comment.

Current C4 captures also witness the declared filesystem refusals at
`CerbFS.fs_close:260` (`tests/freebsd/cat.c`, closing stdout), `fs_stat:504`
(`tests/suite/fs/stat.c`) and `fs_read:338` (`tests/tcc/40_stdio.c`, a
nonzero, non-EOF read offset). These are C-triggered runtime failures within
the explicit filesystem boundary, not successful comparisons or a proof of
logical failure propagation. See the [CI reporting record](2026-09-06_ci-reporting-results.md)
for their raw observations and historical classifications.

## The eight pending fuel workers are still separate obligations

| Workers | What prevents closure |
|---|---|
| Compatibility trio: `are_compatible_aux`, `are_compatible_params_aux0`, `are_compatible_params0` | Recursion follows pointer/function references, not just by-value layout dependencies. Legal recursive-pointer cross-TU input can make upstream recur indefinitely. A by-value acyclicity hypothesis is insufficient. |
| `hack` | Pure `value` result, step-until-value recursion; `finalize` itself returns a pure `driver_result`. Neither becomes absorbing by annotating unrelated monadic failures. |
| `to_pure`, `to_pures` | Recursive arguments can be results of `subst_pattern`; failure-dependent results have no proved structural size bound. Making a failure a transparent default would erase the required failure semantics. |
| `many`, `many1` | Need parser progress/consumption hypotheses and a failure/exhaustion distinction. Input sits inside `ParserM`'s function argument. A parser that accepts without consuming defeats a length-only argument. |

The existing fixture theorem handles `finalize` only under its explicit
singleton-thread and value-arena hypotheses. It does not prove every
reachable terminal state has that shape. The 13 fuel zero-case lemmas are
not general absorption or sufficient-fuel monotonicity theorems. Layout
measure theorems retain their `CerbTagsWf.Acyclic` hypotheses; frontend
enforcement of those hypotheses remains a separate defect/obligation.

## Recommended correspondence design for final discussion

Keep the shared Lem source and OCaml output as reference. Generate a strict,
explicit-result Lean entry before unused-binding/argument elimination can
erase a failure. Do this in Lem's typed translation, with an explicit local
scope and a small first vertical slice. Do not implement a second handwritten
C semantics or project mutable state through a pure function.

The proposed interface shape is:

```lean
inductive FailureKind | deliberate | unsupported
structure FailureInfo where
  kind : FailureKind
  site : FailureSite
  message : Message
inductive Evaluation (α : Type) where
  | value : α → Evaluation α
  | failed : FailureInfo → Evaluation α
  | exhausted : Evaluation α

-- Generated together from the same typed Lem declaration:
f_value   : Inputs → ResultType
f_checked : Inputs → Nat → Evaluation ResultType
```

`FailureSite` is a stable source identity; `Message` must have a stated byte
relation to the reference message. Those are interface parameters here, not
new implemented opaque atoms or a decision to normalize Unicode. Exhaustion
is separate from model failure and from ordinary model UB/error values.
For monadic declarations the checked result must compose through the actual
state/ND effects, retaining failure-time state and semantic output. Pure
callback arguments must be translated too; changing only the callee's final
return type leaves the measured unused-argument hole open.

The contract needs all of these directions:

1. **Successful-result soundness:** a checked successful result corresponds
   to a successful strict reference evaluation with the related value.
2. **Completion and success completeness:** a finite successful reference
   evaluation admits sufficient fuel, and every larger fuel produces the
   related success. Include a concrete successful witness.
3. **Faithful failure, both directions:** for every finite deliberate
   reference failure there exists a sufficient budget such that every larger
   budget reproduces its related class/payload. Every reported checked model
   failure must have that reference failure. Exhaustion is separate and may
   occur below the sufficient budget. An unsupported-domain guard has its
   own explicit precondition/refusal contract; it cannot masquerade as a
   reference model failure or discharge this completeness obligation.
4. **Connection to the value definitions:** under a proved success-domain
   condition, relate `f_checked = .value v` to `f_value = v`. An unrestricted
   equation over a value definition that erases failure cannot express the
   required reference behavior.

For the representative `unused_binding`, strict translation is the equivalent
of `do let _ ← stop_checked n; return n + 1`. Its result is a deliberate
failure for every `n`; the old value equation still reduces to `n + 1`.
Both statements are expected, and their success-domain condition is false.
For `positive_control n`, the checked result must be `.value (n + 1)` at
sufficient fuel. This witness rules out an always-failing implementation.
For the mapped projection, propagation must be proved through traversal
before length/projection discards elements, not inferred from the native
panic. These examples define the first transform's acceptance cases.

For expressions with several potentially failing operands, the translation
must also preserve the reference evaluation order at the pinned toolchain
boundary. Add multiple-failure and effect-order probes before expanding the
vertical slice, and state any order-independence precondition explicitly.
A generic claim of strict evaluation does not determine which failure payload
or failure-time state should survive.

Kernel-checkable obligations include generated typed-result propagation,
strict evaluation-order certificates for the supported Lem constructs,
conditional connection to the existing value definitions, and sufficient-fuel
results under explicit preconditions. A generic account of strict Lem
evaluation may support the compiler proof; it must be derived from the same
typed input, not maintained as another Cerberus model. Equating that account
with the actual OCaml compiler/runtime remains an external reference boundary
unless separately formalized. The independent and fork/Lean differential
lanes remain required evidence on that boundary.

Start implementation, if adopted, with the measured discard mechanisms and
one real memory/driver path. Require unchanged OCaml artifacts, positive and
failure controls, complete observations, printed theorem cones and a cold
client. Then migrate the seven seams and the corrected generated inventory
by channel, handling the Core-run and typing error vocabularies explicitly.
Retain every unresolved pure site with an owner and a checked precondition or
repair obligation. Broad lifting, a global success-domain assumption, new
semantic defaults, or a type change to `hack`/`finalize` is a subsequent
reviewed decision, not an automatic consequence of this census.
