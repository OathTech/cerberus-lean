Highlights the charter called out by name:
- **ffs(-1): oracle `Specified(1)`, Lean `Specified(0)`.** `-1` is all-ones

  `gcc_builtin_generic_ffs` clamps via `Int.toNat` → 0. (sem:G4)
- **realloc-UB: oracle `UB179c`, Lean `UB179a` (non-heap); oracle `UB179d`,

  one null pointer`, `Memory WIP: ge_ptrval`); Lean silently returns
  `Specified(0)` — a kill-path turned value-path. (sem:G1)
- **memcpy OOB / read-only, memcmp-uninit:** oracle kills
  (`UB_CERB002b_out_of_bound_store`, `UB064_modifying_const`) or
  hard-crashes on its own assert (memcmp-uninit → `CRASH`); Lean silently
  returns a value. (sem:G2)
- **G6 conflation:** `equal_sym` returns `true` on two distinct,
  hash-colliding identifiers — kernel-checkable, not a probability claim.

### Oracle-wrong finds (three-way vs gcc + upstream)

- **`g5-decode-question` ('\?') is ORACLE-WRONG.** Three-way: **gcc/C11
  §6.4.4.4 = 63** (`\?` is a *standard simple-escape sequence*);
  **oracle** `decode.ml` has no `"\\?"` entry, falls to the octal
  validator, and **failwiths** (`Failure("decode_character_constant,
  started like an octal constant, but failed: ?")`, exit 125); **Lean**
  silently decodes to 0. So *both* backends are wrong, and the oracle's
  wrongness is a genuine upstream bug (a legal escape rejected). **Do not
  fix-to-match.** Recommended disposition: (a) file the upstream bug (`\?`
  missing from `decode_character_constant_aux`); (b) in the immaculate
  semantics, decode `\?` → 63 (C-correct, gcc-agreeing) and record the
  deliberate oracle divergence in-code + a lembugs/notes entry. Expected
  post-fix lane shape: a NEW status (Lean-right vs crashing-oracle), NOT
  MATCH — flagged in the baseline header so the flip is deliberate.
- **`g5-decode-multichar` ('ab') — oracle fail-closed is DEFENSIBLE.**
  gcc = 24930 (implementation-defined multi-char int); oracle failwiths
  (rejects impl-defined multichar — acceptable); Lean silently returns 97
  (first char). Fix: Lean fail-closed to agree with the oracle's
  rejection. Post-fix: both fail-closed (agreed-rejection shape, still not
  a MATCH token).
- **`g2-memcmp-uninit` — oracle assert-CRASHes.** The oracle's per-byte
  memcmp `assert false` on an unspecified byte is itself ugly (a crash
  where a clean UB kill belongs), but it is fail-closed. The immaculate
  Lean fix (checked per-byte load → clean kill) will be *more correct*
  than the oracle here; expect a justified non-MATCH (Lean kills cleanly;
  document the oracle-crash divergence). Not an upstream filing — it is
  fail-closed, just inelegant.

### De-globalization behavior-preservation protocol (be:G3/S5, batch B1)

The bar is **byte-identical generated output before/after each refactor
batch**, cache-disabled (the certification-integrity rule for build-rule-
adjacent changes). Procedure:

1. **Snapshot.** With the pre-refactor lem, regenerate the full generated
   tree (`make lean-prelude-src` on cerberus + `tests/comprehensive: make
   lean` on lem) into a pristine reference dir. Record a `sha256sum` manifest
   of every generated `.lean` (cerberus `lean_frontend/generated/**` and the
   lem `lean-lib/LemLib/**`).
2. **Cache-disabled rebuild.** After the refactor, regenerate from clean
   (no incremental reuse: `make clean-prelude-src prelude-src`, and for lem
   a clean `dune build` of the backend + a clean generation run — never
   trust mtimes, per the arc-13 hotfix lesson `dune trusts its incremental
   db over the filesystem`).
3. **Byte-compare.** `diff -r` + `sha256sum -c` the new tree against the
   snapshot manifest. **Zero diff is the pass.** Any diff is either a bug
   in the refactor (fix it) or a deliberate, reviewed improvement (then the
   snapshot is re-taken in its own commit with justification — but the
   default expectation for a *behavior-preserving* de-globalization is
   exactly zero).
4. **Then the full bar** (Tier A+B) on the byte-identical output — proves
   the refactor changed the compiler's internals, not its output.

Because B1 is L-priced and the biggest churn, land it as several
byte-neutral sub-steps (e.g. one ref-cell family → state-record field at a
time), byte-comparing after each — the register notes each ref already
carries a `Fun.protect` save/restore discipline, so the moves are
individually mechanical. If byte-neutrality cannot be held for a sub-step,
that sub-step **parks with evidence** (charter risk rule: the arc floor is
F-row + Ott + Set + guard + re-mark; be:S16 file-split is explicitly
deferrable).
