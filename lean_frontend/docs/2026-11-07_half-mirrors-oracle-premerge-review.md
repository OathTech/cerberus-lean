### F3 (P2, should-fix) — the decoder's third live caller, the `argv` store, is an unprobed crash on both engines

`frontend/model/driver.lem:1792` (`prepare_main_args`) stores every byte of every program argument through
`Decode.decode_character_constant (String.toString [c])` — the raw character, with no `escaped_char` — so a backslash
or any byte outside the single-character table in `argv` dies in the decoder's catch-all. The record (§1, §2.2, the
tray-11 comment in `decode.ml`) names `store_chars_in_array` as "the one caller" of `escaped_char`, which is true, but
the charter's vicinity rule asked for the decoding vicinity and this caller of the DECODER is in it. Verbatim
(`int main(int argc, char **argv) { (void)argc; return (unsigned char)argv[1][1]; }`, `--nolibc`, `--args`):

```text
$ main.exe --nolibc --exec --batch --args='a\b' argv.c
cerberus: internal error, uncaught exception:
          Failure("decode_character_constant, invalid constant: '\\'")          (rc 125)
$ main.exe --nolibc --exec --batch --args="$(printf 'a\xc8b')" argv.c
          Failure("decode_character_constant: invalid char constant ==> \200")  (rc 125)
$ cerberus-lean --batch --first --args 'a\b' argv.json
PANIC … cerberus-lean stop ["1","UPSTREAM_CRASH","CerbDecode.characterSlash","Mirrored upstream failure: decode_character_constant: invalid char constant ==> \\ (decode.ml:199-200)", …]   (rc 134)
$ gcc -std=c11 -w -O0 argv.c && ./a.out 'a\b'; echo $?
92
```

The mirror holds (both engines crash identically; the zero-discrepancy rule is met), so this is not a defect of the
slice's fixes; it is a sibling of trays 10/11's mechanism (the argv store needs the same right-inverse the formatted
store got, or the crash-to-refusal arm) that record §3.3's closing claim — "No sibling wrong on conforming input
remains in the vicinity other than the known-and-filed library items (11, 12) and the crash-to-refusal items (4, 5,
6, 8)" — does not cover. Fix in this slice: a row in the record's findings table and the TODO crash-to-refusal
item (3) naming the argv shape beside the UCN one; the code change is a Lem edit (`driver.lem`, a generated delta) and
belongs to that item, not to this "hand-written OCaml only" slice.
