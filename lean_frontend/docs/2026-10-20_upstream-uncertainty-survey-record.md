### 2.1 Cluster A: anonymous struct/union members (NEW; SILENT WRONG)

Root: `desugar_struct_declaration` (cabs_to_ail.lem:2709-2719): for a struct-declaration with no declarators it calls `E.get_anonymous_struct_or_union base_ty` and on `Just membrs` returns `membrs`: the anonymous member's members are spliced into the containing aggregate's member list. The oracle's own Ail print shows it (`--pp=ail` on un-06): `struct S { signed int b; char c; signed int d; };` for `struct S { union { int b; char c; }; int d; }`. Consequences: an anonymous union's members get separate storage (no aliasing, wrong `sizeof`/offsets); an anonymous struct keeps its layout only while its alignment does not exceed its predecessor's (ax-01/02); brace-elided initializers treat every member of the anonymous union as a slot, so everything after it is one slot late (an-01, un-03/05/06/09/11) and a braced sub-initializer becomes a false `UB081` (an-08, un-12). Designated initializers naming the members work (an-03/06/07, un-10): name lookup is the one thing flattening gets right. The `this may be WRONG ==> anonymous` prints (cabs_to_ail.lem:144-207, :336, :509, :526, :3237, :3282; desugaring_init.lem:572, :588) are upstream's doubt at the initializer-path layer; the layout error is unmarked. C17 6.7.2.1#13 makes an anonymous member's members members of the containing aggregate for naming; the anonymous member remains one member with its own storage, and a union's members overlap (6.7.2.1#16, 6.2.6.1#7). The parity-detective probe `tests/parity-probes/probes/anon_struct_union.c` (2026-08-30, "AGREE … anonymous struct+union in struct (42)") only reads named members and could not see this; ax-03 is that shape with a layout check.
