### Walker findings of record (implementation deltas vs the design)

* **dnms factorization** (§2 above): round CLASSES live at the
  `advance_*` level + per-round `step_ctx` discovery facts, not as
  per-class dnms wrappers.
* **`hfuel` wildcard pattern**: `@[app_eq]` laws put a bare variable
  in the fuel position + an `hfuel : fuelS = fuel + k` hypothesis
  discharged by Nat-offset unification, so one law covers literal and
  symbolic fuels (DiscrTree cannot match `999999` against `?f + 1`).
* **Spine normalizer** (`normSpine`): lazy unification assigns
  computed values (step_ctx results) as unreduced redexes invisible to
  DiscrTree keys; the walker normalizes computed-value hypotheses
  (`lhs = ?m` with bare-mvar RHS) to bounded-depth constructor spines
  before matching.
* **App-crossings are LAWS ONLY**: the raw-`rfl` fallback is banned
  for `app`-shaped side hypotheses — a raw-whnf'd crossing (measured
  at the T1 load round) synthesizes junk states that defeat dispatch
  and blow term-size; the walker STOPS instead (the semantic/
  mechanical division, mechanized).
* **Budget accounting** (heartbeat doctrine compliance): each walker
  ROUND and each `app_walk_step` runs in a fresh heartbeat window
  CAPPED at (never above) the ambient per-declaration budget —
  accounting parity with the one-declaration-per-round arc-7 style
  this replaces; per-candidate attempts run under a 50k-heartbeat
  sub-cap with runtime exceptions caught (fail-fast, golean
  GoWalk discipline). No maxHeartbeats is ever RAISED anywhere.
* **Chain-first `app_walk_step`**: `exact`-first would unify a step's
  RHS against the goal's terminal RHS = a whole-remaining-run
  reduction grind (measured: alone trips the budget on the T1 chain).
* **Kernel deep-recursion finding**: carrying the
  `advance_step`-branch defeq through implicit unification sends the
  KERNEL into deep recursion; the pinned explicit equation
  (`advance_action_unfold` + `rw`) keeps the check linear.

### 4.3 Findings (the park's cause — design-level, recorded for the
    operator per park-don't-improvise)

* **F-T5-1 (St-family contract falsified).** The design §2 fixed
  `St i = mkDrv (thLoop i) (memLoop (sVal i) i) rs (trL i) (n0 + r*i)`
  with a CONSTANT `rs`. Measured: every iteration crosses TWO
  Neg-action rewrite rounds (`rstau[Neg Action]` — the store-exclusion
  transform, a round class ABSENT from the design's §1.2 table), each
  drawing a fresh excluded-id AND a fresh symbol from the run-state
  supplies; the fresh syms are BOUND INTO THE ENVIRONMENT as unit
  bindings that persist — the env DOMAIN GROWS by 2 per iteration
  (census: 26 → 28 keys across consecutive loop heads; ids
  1048576+2i). So `rs` varies (aid +7/iter, sym +2/iter, eid +2/iter)
  and the env is a genuinely growing tree — the invariant family
  needs recursive env/rs/trace families with lawful-map lookup
  lemmas (the P2-route generalized from bytemaps to environments),
  and the walker's mechanical `rfl` discharges do NOT apply at
  symbolic-env lookups. Workable (T4's EnvHyp precedent pins the
  fresh-draw seed; the drawn ids are closed functions of i; the
  banked s1-s4_t5 env-genericity is exactly what the
  hypothesis-mediated route needs) — but it is a DIFFERENT St
  contract than the blessed design fixed, and re-fixing it is an
  S1-design-level decision, not worker improvisation.
* **F-T5-2 (normalization at program scale).** The walker synthesizes
  post-states lazily; without the design's app_norm normalization
  pass, mid-walk states carry unreduced discovery/eval residue that
  each subsequent round (and each segment-boundary defeq) re-forces.
  At T1 scale this is absorbed; at t5's program size (~150 Core
  nodes) a single entry-block round's discharge chain measured ABOVE
  one ambient heartbeat window — the walk stops inside the entry
  block. The fix the design names (app_norm state normalization) must
  be TYPE-AWARE at this scale: full normalization of arena/env
  components, fixture-name preservation (t5File, memD3 must not
  unfold), and TreeMap-value OPACITY (whnf of map inserts materializes
  well-formedness-proof-carrying internal tree literals). This is a
  walker-v2 design item, not a tuning knob.
* **F-T5-3 (budget-structure lesson, measured).** A restructure
  giving nested discharge attempts their own fresh heartbeat windows
  (attempted for T5 scale) REGRESSED the T1 calibration — segment
  boundary defeqs depend on the walk's assignment LAZINESS, which the
  window structure silently changes. The committed walker keeps the
  commit-2 structure (50k-capped candidate windows; per-round ambient
  windows) plus the mdata fix; the window/normalization interplay is
  part of the walker-v2 item. Verbatim trip (the T5 entry-block walk
  under the restructure):
  `(deterministic) timeout at «tactic execution», maximum number of
  heartbeats (200000) has been reached […]` (truncation marker added
  at the pre-merge audit, B F4).
* **F-T5-4 (elaborator overhead on action rounds).** The
  perform-layer route makes a memory-action round mechanical in
  PRINCIPLE (all laws proved, pinned, registered), but the walker's
  isDefEq-driven discharge of a T1 LOAD round measured ~10x the
  hand-proof's elaboration cost (>1 ambient window vs ~1 s) — sharing/
  caching work in the discharge engine is part of walker-v2.
