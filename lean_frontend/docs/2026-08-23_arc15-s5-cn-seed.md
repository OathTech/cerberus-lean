## Targets (real external code, clean-room deps/cn, BSD-2)

Chosen from the corpus ensures-survey (candidates = non-.error files

family was the doctrine's named on-ramp):

**`deps/cn/tests/cn/swap_pair.c`** — the swap family: the first
corpus target whose `ensures` is a functional relation between pre-
and post-state MEMORY. CN spec verbatim (also cited in
`SpecLab/CnSeedHarness.lean`):

```c
void swap_pair(unsigned long int *pair_p)
/*@
requires
    take pairStart = each (i32 j; 0i32 <= j && j < 2i32) {RW(array_shift(pair_p, j))};
ensures
    take pairEnd = each (i32 j; 0i32 <= j && j < 2i32) {RW(array_shift(pair_p, j))};
    pairEnd[0i32] == pairStart[1i32];
    pairEnd[1i32] == pairStart[0i32];
@*/
```

**`deps/cn/tests/cn/cn_inline.c` `lookup_size_shift`** — the
cn_function-bound scalar. CN spec verbatim:

```c
/*@ function (i32) lookup_size_shift_cn (u32 sz) @*/

static inline int
lookup_size_shift (enum size sz)
/*@ cn_function lookup_size_shift_cn;
    ensures return == lookup_size_shift_cn(sz); @*/
```

(the file's second contract, `f`'s `ensures return < (1000i32)`,
gets a pure mirror — see below.)

Models: swap `PairInput = UInt64 × UInt64`, `modelFn = ⟨b, a⟩`, and
**Wf is VACUOUS** — the first rung with a FULL model domain (every
u64 pair is realizable; the 16-byte stream is total on its index
space). lookup `lookupSizeShift : Int → Int` mirroring the switch
(0↦12, 1↦8, 2↦2, default↦0), `LWf = 0 ≤ sz < 2^31` (the closed
program builds the argument as a nonneg int and converts to
`enum size`; ≥ 2^31 is the harness's 254 arm). Codecs: swap = two S0
`encodeU64LE`s (ZERO new codec definitions); lookup = S0 u32le +
the S1 i32le result codec.

## THE PARKED FINDING: the CoreParser enum-ctype gap (S5-E4)

The lookup family's PINNED layer is **parked**: its oracle dumps
carry the ctype literal `'enum size'`
(`load('enum size', …)`, `conv_int('enum size', …)`,
`are_compatible`, `Ivalignof`), and the hand-written Core TEXT
parser (`lean_frontend/CoreParser.lean` — SEMANTICS SURFACE, outside
this worker's write scope) has no `enum TAG` arm in its quoted-ctype
grammar: `--parse-core` refuses the dump at top level. Minimal
repro: ANY C program touching an enum-typed object (verified: a
5-line switch WITHOUT enum parses fine; adding the enum parameter
reproduces). The EXEC pipelines are unaffected — the cabs-json path
carries enums natively (13 sweep samples + plants green, incl.
non-enumerator and 2×10^9-class values through the int→enum
conversion). Disposition per park-don't-improvise (the S3
leak-oracle-leg precedent): the lookup fixtures stay committed as
the parked layer's inputs + reproducers; the emitter processes the
swap family only; PRICE S (add `enum TAG` to CoreParser's quoted-
ctype grammar + the emitter already has the `Enum0` pp arm; re-run
`speclab-emit-seed` extended with the drafted lookup plan — the
2-param zip table is in the S5 batch-1 history). Register S5-E4;
inventory row in the results doc.

This is the lab working as designed: the FIRST corpus construct
whose oracle dump the pinning path cannot re-parse is C's most
ordinary enum — surfaced by trying real corpus code, not by reading
the parser.
