### D1 — The accumulator (lem body change) and the flipped reproducer
**Goal (fixed):** thread an assumed-compatible accumulator through the mutual block so that the cross-TU `Struct/Struct` and `Union/Union` arms return `true` for a tag pair already under comparison on the current path, and otherwise compare the members with the pair added. Precisely:

- `env` becomes the triple `(tagDefs1, tagDefs2, assumed)` with `assumed : list (Symbol.sym * Symbol.sym)` — a LIST, not a `set` (reason: the sufficiency proof in D2 reasons about membership and counting; Lean core has every `List` law needed, LemLib has no `Pset` laws; the OCaml side gets lem's `List.elem`, semantically the set-membership test; amend draft 37's remedy wording accordingly in D4). The entry `are_compatible` passes `(tagDefs, tagDefs, [])`.
- In each cross-TU arm, AFTER the same-name test and BEFORE the two lookups: `if List.elem (tag1, tag2) assumed then true else …`; the member comparisons (including the flexible array member) run with `(tag1, tag2) :: assumed`. Every other recursive call (the structural arms, the local shadow at `:89`, `are_compatible_params_aux`/`are_compatible_params`) passes the CURRENT `assumed` unchanged. The accumulator is passed DOWN only, never returned (a path-set, not a memo — siblings do not see each other's additions). Nothing else in the block changes: same arms, same order of tests, same `error` calls, same results.
- Why the results are unchanged on every previously-terminating input (write this argument into the record in your own words; it is the correctness claim of the slice): a cross-TU hop node is determined by `(tagDefs1, tagDefs2, tag1, tag2)` once `qs1 = qs2` and the name test pass, and its member subtree does not depend on the outer qualifiers; so if the same pair recurred on a path of the ORIGINAL's recursion tree, the subtree would repeat and the original would not terminate. Hence on every input where the original terminates, no pair recurs on any path, the new membership test never fires, and the two functions compute the same tree. The new function terminates on every input because each hop adds a pair from the finite product of the two tables' domains that was not yet present.
