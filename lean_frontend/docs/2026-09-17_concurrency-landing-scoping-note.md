## 1. What the branch establishes today, and against what (measured on the branch)

**There is no oracle for concurrent behaviour.** At the merge base `b9aeedcb4` upstream's `--concurrency` dies with `internal error: CONCURRENCY IS BROKEN` (Phase-0 charter §2.1; the branch's tray draft on it); pristine upstream therefore refuses or crashes on every concurrent program, and the fork-vs-Lean rule has no third party to compare with. The branch's evidence stands on three legs:

1. **Engine agreement by generation.** The scheduler, the selector (`Core_run_aux.concurrency_model = CM_sequential | CM_sc`, `core_run_aux.lem:37-39`), the execution construction and the race verdict are written once in Lem and generated to both targets. The litmus lane (`scripts/test_litmus.sh`) requires oracle set = Lean set per row (its "(1)"). This is a MIRROR property, not a correctness property.
2. **A mechanical SC reference plus recovered upstream sets.** `tests/litmus/sc_reference.py` derives the outcome set of each SC-class row from a hand transcription of the program (its own header: *"NOT an oracle for the engines"*), and the sets are cross-checked against upstream's deleted 2017 `tests/concurrency/` expectations recovered from `backend/common/tests.ml:77-89`. 30 programs, three-way (`S7` E1: 30/30).
3. **A per-trace bridge check.** Every race-free trace's recorded candidate execution is checked at runtime against the library's SC-accesses consistency tree `sc_accesses_consistent_execution` (`frontend/concurrency/cmm_csem.lem:2077-2094`: `assumptions`, `tot_empty`, `well_formed_threads`, `well_formed_rf`, the two locks leaves, `consistent_mo`, `sc_accesses_consistent_sc`, `consistent_hb`, and the `consistent_rf` node — `det_read`, `consistent_non_atomic_rf`, `consistent_atomic_rf`, `coherent_memory_use`, `rmw_atomicity`, `sc_accesses_sc_reads_restricted`). A failing leaf is a typed internal error, plant-tested by corrupting `rf` (S3). Racy traces take the `UB005_data_race` verdict from `data_races` over the recorded `hb` and are not required to pass the tree (S3 record: "the bridge is the invariant over the race-free traces").

The branch's `VALIDATION.md` claim 5 states this honestly: *"a member of the C11 model family, checked per trace, not assumed … Sampled … The theorem-shaped statements … are recorded as owed, not claimed here."* No external oracle exists on the box: `herd7` and `cvc5` are not installed; `/usr/bin/z3` is; the z3-based `backend/bmc/` (C11/RC11/Linux modes) is not built.

**What the repository already carries** (the operator asked): the Cambridge concurrency work is present — the cppmem axiomatic C11 model `cmm_csem.lem` (3,420 lines) with its named variants (`single_thread`, `locks_only`, `relaxed_only`, three `release_acquire` flavours, `sc_accesses` (`:2099`), `sc_fenced`, `with_consume`, `standard` (`:2483`), `tot`, …), Nienhuis's operational model `cmm_op.lem` with the Isabelle equivalence proofs (`Cmm_op_proofs.thy`), `linux.lem`, and the bmc backend. The repo's "several models" — `memory/{concrete,symbolic,vip,cheri-coq}` — are OBJECT/PROVENANCE models, orthogonal to concurrency. What was missing was EXECUTABILITY: the axiomatic variants judge candidate executions but do not produce them, and upstream's producing path is dead. The branch built the executable interleaving instance and validates each trace against the repository's own SC-accesses predicate — the strongest part of the story, to be stated as such.

## 2. Where "right behaviour" is unsettled (recorded on the branch; decided here)

1. **The agreement lemma.** Accepted as a Phase-0 obligation at the consumer's request (S1 interface review Q4), stated in S5 §4 as "for every Core file `f` with `epar_free f = true`, `drive … CM_sequential …` and `drive … CM_sc …` yield the same verdict list", NOT discharged (S5 §4, S6 §1); the audit's M1: the statement is FALSE without the fragment premise (`CM_sc` refuses a relaxed atomic that `CM_sequential` runs) — the correct statement carries `sc_fragment_ok f = true`. Its substance is a single-thread SC-consistency theorem: on one thread the recording, the bridge and `data_races` are inert.
2. **The recorded non-parametric point** (DESIGN.md on the branch, "temporal boundary; mover = Phase 1"): the instance obtains a load's value AT ISSUE from concrete memory; the C11 operational model fixes it when the read is COMMITTED. The interface does not admit deferred values. A consumer proof written against `CM_sc`'s shape can bake in "loads are immediate" — the seam a model switch would tear.
3. **Locations are pointer values** (the upstream `FOOTPRINT` dummy), so mixed-size overlapping accesses are not related as races (audit M3, owner Phase 1).

## 3. The trust story we land under ([AGENT], agreed [USER 2026-09-17])

**(a) The consumer's model is `CM_sc`; `CM_sequential` is the oracle-comparison instance.** Every differential lane — pristine, fork, gcc, Lean — runs with concurrency OFF, so all sequential validation evidence is evidence about `CM_sequential`. cerberus-sl proves against `CM_sc` for everything. The ONLY thing carrying the sequential evidence over to the consumer's model is the agreement lemma. It is therefore the TRANSFER PRINCIPLE of the trust story, not a courtesy: a landing-slice deliverable, stated with the fragment premise.

**(b) An empirical twin of the lemma.** A lane that runs the existing exec corpora under `--concurrency=sc` on both fork engines and requires the same verdicts as the sequential runs, with fragment refusals reported as their own class — exercising the recording machinery's inertness on thousands of programs, not thirty litmus rows. Pristine cannot join this lane (no concurrency upstream): it is a fork-vs-Lean lane by nature, and WP-O's register/doctrine gets a class for "behaviour absent upstream".

**(c) The command-line default stays `CM_sequential`** (matched mode against pristine requires it; the default is a harness choice per the no-magic-values rule, never a definition). `VALIDATION.md` says plainly: the consumer's model is `CM_sc`; the sequential instance is the oracle-comparison instance; the agreement lemma is the bridge.

**(d) The soundness theorem — the bridge as a theorem.** For every fragment program and every trace the `CM_sc` scheduler produces, if the recorded execution has no data races then it satisfies the SC-accesses consistency tree. Provable: an interleaving is a total order `T` on actions; the construction gives `sb, asw ⊆ T`, `rf` = the `T`-latest same-location write, `mo` = `T` restricted to atomic writes per location, `sc` = `T` restricted to seq_cst actions; then `hb ⊆ T` (acyclic), `mo` agrees with `hb`, an SC read reads the last SC write, coherence leaves are order embeddings, RMWs read their `mo`-predecessor because the scheduler performs them atomically, the locks leaves are vacuous in the fragment; the race-freedom premise is what makes `consistent_non_atomic_rf` hold. Two layers, kept apart: (i) a small hand-written theory of executions generated from a total order, each leaf a general lemma — textbook, clean; (ii) a specification lemma that the driver's RECORDED execution equals that abstract construction on the trace's order — a statement about generated driver code (the action recording, the `sb`/`asw` annotation walkers) over LemLib sets; canon-first, never unfold the generated tree in a goal; STOP rule on grind. Consequence: claim 5 goes from "sampled" to proved; the bridge's internal-error branch becomes provably dead (keep as plant-tested defence in depth, or delete — an operator decision at landing).

**(e) Interface versus instance.** State separately what a consumer may assume of ANY instance (a thread pool; action granularity; typed refusal outside the fragment; a data race is UB; the selector is a total, kernel-transparent argument of `drive`) and what is true only of `CM_sc` (immediate loads; seq_cst only; pointer-valued locations). cerberus-sl is asked to write adequacy against the former only.

**(f) Model-switch safety is the CONVERSE theorem.** A fault-avoiding separation logic proves race freedom as part of every triple; the DRF-SC guarantee says a race-free program's behaviours under the weak model are exactly its SC interleavings; together, every cerberus-sl proof under `CM_sc` remains valid when the instance switches to a weak-memory model — PROVIDED DRF-SC holds for that instance. The converse (every consistent SC-accesses execution of a race-free fragment program is produced by some interleaving; and its analogue for the future weak instance) is the named PRECONDITION of any model switch. It is a real theorem (Batty et al. for the standard model); it goes on the roadmap by name, proved later, never dropped.

**(g) An independent litmus oracle at the next network window.** `herd7` with the C11 `.cat` model (later `linux-kernel.cat`) — the role gcc plays for the sequential lanes. Until then the litmus evidence is Cerberus checking Cerberus plus one hand transcription, and VALIDATION says so.
