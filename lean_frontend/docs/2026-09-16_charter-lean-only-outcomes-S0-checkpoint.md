## 6. Post-execution errata (orchestrator [AGENT], 2026-09-16) — what the probes showed this charter had wrong

The slice ran to S0.6 on `arc/lean-only-outcomes-S0` (prototype head `8f8c4dfe7`, unmerged by design; its record, addendum and evidence land via `docs/lean-only-outcomes-S0-record`). Each item below was re-verified by the orchestrator against the prototype and the mainline artifacts.

- **§1 "`kill_reason`'s default is `Error0 default default`" — WRONG.** The generated primary instance is UNCONSTRAINED (`instance {err} : Inhabited (kill_reason err) := Undef0 default default`, `generated/Nondeterminism.lean:65-66`); the `Error0` body at `:68` is the low-priority fallback. So `(default : kill_reason err) = Undef0 default default` by `rfl`, and the hazard on this type is NOT that the default becomes a stop (it stays `Undef0`); the hazard is on `Undefined.t` (unconstrained `a`: `Error default default` → `Stopped Exhausted` after the extension). Both are pinned in `test/Unit/StopDefaultsTest.lean` on the prototype.
- **§1 "`backend/common/dune:5` does not [treat warning 8 as fatal]" — WRONG.** dune's dev-profile `:standard` flags make warning 8 an error; `(:standard -w -27)` keeps it. The compiler forced arms in `backend/common/driver_ocaml.ml` (a `batch_output` variant + printer + two arms) and `.mli`, AND in `ocaml_frontend/rewriters/core_peval.ml` (three arms) — a hand-written OCaml file no design document had listed. `smt.ml`, `interactive_driver.ml`, `cerbcore.ml` are dune-excluded (dormant).
- **§1/S0.1 the `skip_instances` candidate — FAILS.** The backend assumes an unconditional `Inhabited` for a census-absent type (`lean_backend.ml:474-478`) and still emits `default := Stopped default`; Lean then fails to synthesize `Inhabited interp_stop` (`generated/Undefined.lean:1864`). No generation-time demand fires. `skip_instances` also leaves `deriving BEq, Ord` in place (`DESIGN.md:494` overstates). The only mechanism is a small lem-lean declare — `declare {lean} inhabited_exclude type t` (census `Inh_none`; the existing usable-constructor rule then excludes `Stopped`) — a PAIRED lem-lean slice before S1a (decision R1).
- **§3 "the Lean build enforces completeness" (implicit in §2 S0.2) — WRONG.** lem emits a `failwithI "Incomplete Pattern"` wildcard for a `.lem` match lacking an arm, so a missing arm does NOT fail the Lean build; it becomes a pure failure site at runtime. The arm inventory therefore comes from the OCaml compiler (warning 8 fatal in both `ocaml_frontend` and `backend/common`) and from lem's own `-wl_pat_exh` list — never from the Lean build. (A lem-lean item: a generation-time error for incomplete matches on the Lean target would close this fail-open shape.)
- **§1 "`core_run.lem:165` can meet a stop" — REFINED.** Its element function `step_eval_pexpr` is MEASURED (never a stop at sufficient fuel); stops CAN arise in element k at `core_run.lem:1380` and `core_reduction.lem:321/1357/1393/1409` (ABSORBING element functions).
- **Consumer cost (S0.5) — the scoping note undercounted.** Beyond the one literal term, TWELVE constructor-match blocks in refined-cerberus (`Round.lean` ×9, `Soundness.lean` ×3) become non-exhaustive under a new `kill_reason` constructor; 18 alias uses migrate only if `CerbND.fuelExhaustedKill := Stopped0 Exhausted` is definitionally the regenerated arms' value (four `rfl` proofs depend on it). Relay with the record's S0.5 table.
