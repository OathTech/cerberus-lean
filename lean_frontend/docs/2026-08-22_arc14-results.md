## 5. The partial-def residue note (sem:N12, discharged here)

The 316 `partial def`s in `generated/` outside the totalized exec slice
plus the ~135 in CoreParser/CabsImport are fenced by the totality gate's
module allowlist rather than per-def justification. Why the residue is
safe: (a) the exec slice — everything the differential verdicts and the
RelSem theorems depend on — is TOTALIZED with an empty allowlist and 60
kernel proofs (arc-3/7 mechanism), so no partial def sits in any proof
cone or exec path the gates certify; (b) the residue is exactly the
PARSER layer (CoreParser/CabsImport: Parsec combinators over finite
input, each fuel-bounded in practice by input length, opaque to no
theorem) and generated code that is dead on the exec path (defacto/cmm
modules, pp helpers), where partiality is a compile-time convenience
with no epistemic weight — nothing quantifies over their graphs;
(c) any MIGRATION of a residue def into the exec slice trips the
totality gate (allowlist is empty; the module scan is fail-closed), so
the fence moves only by deliberate act. The residue is therefore a
BOUNDARY (parsers + dead-code), not a trust gap in any certified
artifact.

at the merge:
