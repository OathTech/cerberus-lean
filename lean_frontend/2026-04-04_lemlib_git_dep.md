# LemLib as a proper Lake git dependency

**Date:** 2026-04-04

## Problem

The CerberusLean lakefile needs to depend on LemLib (the Lem runtime library
for Lean). Currently LemLib lives in `septract/lem-lean` at `lean-lib/`, but
most of its files are generated by `make lean-libs` and not committed to git.

Only 2 of 30 files in `lean-lib/LemLib/` are tracked:
- `LemLib/Bridges.lean` (hand-written)
- `LemLib/Pervasives_extra.lean` (hand-written)

The remaining 28 are generated from `.lem` library sources by the Lem
compiler:
- `Pervasives.lean`, `List.lean`, `Set.lean`, `Map.lean`, `Maybe.lean`,
  `Bool.lean`, `String.lean`, `Num.lean`, `Function.lean`, `Either.lean`,
  `Tuple.lean`, `Relation.lean`, `Sorting.lean`, `Word.lean`,
  `Machine_word.lean`, `Show.lean`, `Debug.lean`, `Basic_classes.lean`,
  `Assert_extra.lean`, plus `*_extra.lean` variants.

The root `LemLib.lean` (hand-written, 789 lines) IS tracked.

When Lake clones the repo as a git dependency, it only gets the 3 tracked
files. Building then fails because the generated modules are missing.

## What needs to change in septract/lem-lean

**Option A: Commit all generated LemLib files to git**

Add all 28 generated `.lean` files under `lean-lib/LemLib/` to version
control. This is the simplest fix. The files change infrequently (only when
the Lem standard library `.lem` sources change), so the maintenance burden
is low.

After this, a downstream lakefile can simply write:

```toml
[[require]]
name = "LemLib"
git = "https://github.com/septract/lem-lean"
rev = "mdd/lean-backend"
subDir = "lean-lib"
```

Steps:
1. Run `make lean-libs` to generate the files
2. `git add lean-lib/LemLib/*.lean`
3. Commit and push
4. Optionally add a CI step that regenerates and checks for drift

**Option B: Publish LemLib as a standalone repo/package**

Split `lean-lib/` into its own repo (e.g. `septract/LemLib`) with all files
committed. This separates LemLib versioning from the Lem compiler, and
makes it easy for any project to depend on it. The `lem-lean` repo would
then reference it as a submodule or note the version correspondence.

This is cleaner long-term but more work to set up.

## Current workaround

We use a local path dependency pointing to a pre-built checkout:

```toml
[[require]]
name = "LemLib"
path = ".lemlib"
```

The Makefile creates `.lemlib` as a symlink to the user's local LemLib build.
This works but requires every developer to have lem-lean checked out and
built locally, and Lake tries to write config/lock files into the LemLib
directory.

## Recommendation

Option A is the quick fix — commit the generated files to `mdd/lean-backend`.
Option B is the right long-term answer if LemLib stabilises and other
projects want to depend on it independently.
