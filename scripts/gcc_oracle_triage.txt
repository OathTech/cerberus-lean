# gcc second-oracle triage ledger — scripts/test_gcc_oracle.sh
#
# Format: <row-key> <TRIAGED_CLASS> gcc=<exit> lean={<byte-set>} <rationale...>
# BY-FILE semantics (2026-08-30 audit follow-up + orchestrator ruling):
# an entry declares the file a divergence-class observer — the file is
# ALWAYS TRIAGED_<CLASS>, even when the two values happen to coincide
# (a layout coincidence is not agreement; counting it AGREE would
# inflate the metric and arm a flip-to-DISAGREE trap if either side's
# layout changes). Fields 3-4 are MACHINE-CHECKED PINS of the observed
# value pair (gcc = native exit byte under the §2.1 byte-stable
# execution recipe; lean = the expected-byte set exactly as the harness
# prints it). On any drift from the pins the row surfaces as an
# unresolved DISAGREE (fatal, row named), forcing re-triage. Classes +
# procedure: lean_frontend/docs/2026-08-30_gcc-second-oracle-design.md
# §4. FAIL-CLOSED both directions: unlisted DISAGREE is fatal; a
# listed file that no longer reaches the compare stage is fatal.
#
# [AGENT 2026-08-30] Entries from the tier-1 baseline run (D2/ADDR,
# design note §2.3 "allocation addresses" row): each program observes
# object-address bits (low byte / mod / division / alignment residue).
# Cerberus's abstract concrete-allocator addresses and gcc's native
# layout (ASLR off, byte-constant initial stack per §2.1) are both
# conforming; neither side is indicted. Pins captured under the §2.1
# normalized execution recipe (audit-response re-capture; the stack
# observers' values changed from the originally recorded ones when the
# environment/execfn normalization landed — see the design note §2.1
# determinism account). Three entries (align-04, intfromptr-05,
# intfromptr-10) coincide with the Lean value under the normalized
# stack — they remain triaged per the by-file rule above.
#
