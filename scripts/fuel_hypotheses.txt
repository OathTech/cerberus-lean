# THE INVARIANT (rows 1-6): the C frontend's tag environment is acyclic in the
# by-value sense — cabs_to_ail.lem:1512 check_members (STD §6.7.2.1#3) refuses a
# member of function or INCOMPLETE type; ail/ailTypesAux.lem:222 is_complete
# makes a by-value Struct/Union member complete only when its tag is ALREADY in
# sigm.tag_definitions (Array iff its element type is and its size is known,
# Atomic iff its inner type is, Pointer regardless of its target); the flexible
# array member's ELEMENT type is guaranteed by the Ail passes — ailWf.lem:76-80
# (ArrayDeclarationIncompleteType, StructMemberFlexibleArrayInArray) +
# genTyping.lem:2346-2349 (StructMemberFlexibleArray): every by-value edge INTO
# a FAM struct is a constraint violation, so the FAM edge cannot close a cycle
# (audit F-A3); an _Alignas(type) member alignment is completeness-checked by
# alignof_ty on the non-agnostic path (cabs_to_ail.lem:2851-2871) — NOT on the
# character-member `Just LT` path (:2882-2883, ailTypesAux.lem:1291-1292; audit
# F-A2, see below). So definition order is a rank on the by-value reference
# graph; CerbTagsWf.Acyclic states exactly that (any rank).
# Row 4 (offsetsof) takes the two-map form: struct tags resolve in the threaded
# map, union tags in the ambient one (impl_mem.ml:173/:255, the mirrored
# upstream asymmetry); at elaboration time the ambient map is empty and the
# form is Acyclic of the threaded map, at run time both are the linked table.
#

# CORRECTLY. One known frontend GAP (audit e9730d1c8 F-A2): `struct A {
# _Alignas(struct A) char c; }` — an ISO §6.5.3.4#1 constraint violation (gcc
